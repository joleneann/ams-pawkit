### Workspace resolution gotchas
- `.npmrc`: `node-linker=hoisted`, `public-hoist-pattern[]=*` (Expo autolinking trips on pnpm symlinks otherwise)
- `metro.config.js`: extend `getDefaultConfig` with `watchFolders = [workspaceRoot]` and `nodeModulesPaths = [appNodeModules, workspaceRootNodeModules]`
- shadcn `components.json` lives in `apps/dashboard/`, NOT root (shadcn does not understand monorepos)
- Override shadcn neutrals immediately on day 1, before generating components: alias `--background: var(--bg-canvas); --foreground: var(--text-primary); --primary: var(--teal);` etc.

### Supabase setup
- **Migrations** as numbered SQL files. Split schema (`0001`) from RLS (`0002`) so you can re-run policies independently when debugging seed.
- **Seed** programmatic via TS using **service-role key** (`supabase/seed/seed.ts`). NOT `seed.sql`; needs Storage uploads, locale-correct names, dynamic timestamps relative to "now."
- **RLS** enabled on every table. Do NOT use `FORCE ROW LEVEL SECURITY`; service-role bypasses non-forced RLS, which is what you want for seeding.
- **Type generation:** `supabase gen types typescript --project-id $SUPABASE_PROJECT_ID > packages/db-types/src/database.types.ts`. Run after every migration.
