Topbar identity study · 2026-05-15

Quiet down the clinic + vet identity

The current topbar leads loud — 40px berry clinic disc + "Animal Medical Services" at 14px semibold ink, then "Dr Sagar Bhongale" at the same weight + 34px avatar circle. The identity ends up competing with the search bar and the actual content. Five options below: the current baseline plus four progressively quieter or restructured layouts. Each panel notes which shadcn primitives it uses.

About Avatar circles. The clinic disc + vet avatar are currently hand-rolled <div> elements. To make them properly shadcn we'd install @radix-ui/react-avatar and add a wrapper at components/ui/avatar.tsx. Each option below could be implemented with either the hand-rolled circles or a future shadcn <Avatar> — flag at the bottom which way you want to go.

Option D

Clinic chip + vet menu

Button · DropdownMenu · Tooltip · Input · (Avatar)

Identity-led but quieter. Clinic logo + "AMS" short name combined as a single compact chip on the left (full name on hover via Tooltip). Vet avatar + first name + DropdownMenu trigger on the right. Both identity blocks are clearly clickable objects, not just labels — matches the modern app expectation. Keeps the clinic-first framing.

Trade-off: Both identity blocks become DropdownMenu triggers — the clinic dropdown might be empty for v0 (just "AMS, Pune" as a static label). That's a minor over-promise. We could leave it as a static chip (no dropdown) and only the vet chip opens a menu.

How to choose. Look at each topbar in context — does it sit quietly so the inbox / billing / broadcasts content can lead? Or does the identity still grab the eye?

My read. B (Avatars only) is the cleanest minimal — but loses always-visible identity. D (Clinic chip + vet menu) hits the sweet spot for me: identity is present but quieter, both blocks read as interactive objects, and it sets up properly for v1+ when there's more than one vet or clinic. A (Quieter type) is the safe small fix if you don't want to restructure.
